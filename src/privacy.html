2. Information the App handles

Lookup subjects and results

You can enter a domain or URL, public IP address, ASN, username, email address, an email-domain-only subject such as email-domain:example.com, or an international phone number. The App processes the lookup request through its local Python service and displays results. The query, results, timestamps, and any case notes are saved in this browser when a case is created or refreshed.

  • Domains: the domain is sent to public DNS and registration sources, certificate search, and passive hostname search. Discovered hostnames may also be resolved through public DNS.
  • Public IP addresses and ASNs: the address or ASN is sent to the applicable public registration service selected using IANA RDAP data. An IP lookup may also query public reverse DNS.
  • Email addresses: the full address is processed by the local service and saved as the case subject. Built-in email checks send only its domain to public DNS and registration sources; they do not check mailbox existence or identity.
  • Email-domain-only subjects: only the entered domain is processed and saved in the case, then sent to public DNS and registration sources for mail-policy and registration checks. No mailbox identifier is collected by this mode.
  • Phone numbers: the number is processed for E.164 formatting on the local service and saved as the case subject. The built-in phone check does not request subscriber, carrier, location, or account information from a provider.
  • Usernames: the App fetches public profile-check definitions pinned to catalog revision 062bcfe48df79fa618e96edc79dc9673f3fe5643; that catalog request does not contain your handle. Before submission, the App displays the selected profile site names and hostnames. If you start the lookup, the handle is sent to those public profile websites. Those sites receive the requests and may record them.

External search shortcuts

If you choose an external search shortcut, the selected provider receives the query in the search URL. This applies to AlienVault OTX, OpenCorporates, and Academic Torrents. An OTX URL lookup includes the complete URL; the App rejects embedded username/password credentials and requires an additional confirmation before sending URLs with a path, query, or fragment. Epieos opens without a query; you enter any email address or phone number directly on Epieos yourself. External shortcut results are not collected or saved by the App.

Cases, notes, and exports

Cases and notes are kept in this browser’s local storage until you delete them, use “Clear saved cases,” or clear the browser’s site data. A case may include its subject, lookup results, collection history, notes, and imported report details. Imported report details can include the source filename and processing counts. JSON or CSV exports are downloaded to a location you choose and may contain sensitive case information. The infrastructure graph is generated in the browser from the selected case, makes no additional provider requests, and excludes account, email, and phone relationship data. GraphML exports contain graph entities, source provenance, provider-reported event dates, and collection times and may reveal the case subject and infrastructure findings.

The Research source guide contains links and summaries of independent tools. Opening a provider details link does not include the case query; if you then search on that provider, its own terms and privacy practices apply.

Imported reports

The report importer reads supported JSON, JSONL, CSV, or plain hostname-list files in the browser. It keeps in-scope hostnames and IP addresses and discards person, contact, and credential fields. The imported file itself is not uploaded by this import feature. The resulting findings, provider source labels, source filename, and import statistics are saved with the case.

File metadata inspection

When you choose a supported image or document for metadata inspection, the browser sends the file and its filename to the local loopback service on your device for parsing. The service processes them in memory and does not save the file. The displayed filename and metadata result stay in page memory and are not added to a saved case by this feature. Metadata can contain location, author, device, or timestamp information.

3. Why the information is used

The App uses the information above to perform the lookup or file inspection you request, display and organize findings, save cases and notes in your browser, and create exports you request. The current local version does not require an account and has no operator-hosted case database. The App does not intentionally use case contents for advertising or sell case information.

4. Who receives information

Lookup values are sent only to the source services needed for the lookup you start, plus a provider you explicitly choose for an external search. For domain cases, you can choose whether the hostname is sent to crt.sh, HackerTarget, or both; DNS and RDAP checks still run. Depending on the feature, other services can include Cloudflare DNS over HTTPS, an IANA-selected RDAP registry, public profile websites in the selected account-check catalog, and the external search providers listed above. GitHub receives a request to download the public profile-check definitions when needed; the username is sent to the profile sites, not with that catalog request.

These services are independent of the Operator. Their systems may receive the query and ordinary connection information, such as your public IP address, request time, and technical request details. Their own privacy notices and retention rules apply. The Operator cannot control how a provider handles information after it receives a request.

Case data is not sent to an Operator database by the current local version. The local Python service suppresses access logs containing request targets and query values and does not keep an application database. Network lookups still leave your device for the selected public sources.

5. Storage and retention

  • Browser cases: cases include your selected domain sources and retain up to five prior compact summaries and provider-specific hostname snapshots for comparison. They remain in local storage until you delete the case, clear all saved cases, or clear site data. The App does not set a separate automatic deletion period.
  • Exports: remain wherever you save them and are under your control.
  • Lookup processing: the local service handles requests while they run and does not maintain a case database or log query values. Provider-side retention is determined by each provider.
  • Metadata inspection: the file is parsed in memory by the local service and is not saved by the App; the result remains in page memory until the page is refreshed or closed.

Local browser storage is not encrypted by the App. Anyone with access to your browser profile or device may be able to access saved cases. Protect your device and browser profile, and avoid using the App for information you cannot safely store there.

6. Your choices and privacy requests

You can review or delete saved cases using the App’s case controls, clear all cases with “Clear saved cases,” and clear the App’s site data using your browser settings. You can also choose not to start a lookup, not to use an external search, and not to import a report or inspect a file. Deleting a local case does not delete information already received by an independent provider or copies in an export you downloaded.

These safeguards do not make your device, browser, network, or third-party providers risk-free. Use an up-to-date browser and operating system, limit device access, and protect any exports.
